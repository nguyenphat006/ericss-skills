## 1. Stack and setup
- Next.js 16 (Turbopack), React 19, strict TypeScript; use **npm** (not pnpm).
- Tailwind CSS 4 (`@theme` in `globals.css`) + shadcn CLI 4.x. The new init command is `npx shadcn init -p <preset>`; the `--base-color` flag has been removed.
- next-intl 4, motion (the new framer-motion), lucide-react, react-hook-form + zod, `yet-another-react-lightbox` for lightboxes.
- prettier + `prettier-plugin-tailwindcss`, eslint `eslint-config-next`.
- Scripts: `dev` is `next dev -p 4000`, `start` is `next start -p 4000`. Pick a port that does not clash with the user's other apps.
- The `AGENTS.md` file generated by `next dev` warns that this is not the Next from your training data: read `node_modules/next/dist/docs/` before using an unfamiliar API.

## 2. Directory structure
```
frontend/
  messages/{vi,en}.json            # UI copy, same key set
  public/Assets/  public/products/  # static images (self-hosted, no hotlinking)
  src/
    proxy.ts                        # next-intl (Next 16: replaces middleware.ts)
    app/
      globals.css                   # design tokens (landing-design-system skill)
      [locale]/layout.tsx  page.tsx  not-found.tsx  [...rest]/page.tsx (catches unknown URLs → 404 with header/footer)
      [locale]/<page>/page.tsx      # THIN page: fetch data, compose sections, metadata
      api/revalidate/route.ts       # webhook from the CMS
    components/
      ui/                           # generated by shadcn
      shared/                       # shared components (Section, ButtonLink, PageHeader...)
      layout/                       # SiteHeader, SiteFooter, menu
      archive/                      # hidden sections, kept for reuse (README is the catalog)
    features/<domain>/              # home, products, materials, about, capabilities, contact
      components/  data.ts  index.ts (public API: only export what the page uses)
    data/<domain>/                  # data types, taxonomy, mocks, server-only data access
    lib/cms/                        # CMS client + mapping API types → UI types
    lib/utils.ts                    # cn() with extendTailwindMerge for custom tokens
    config/                         # site.ts (company info), navigation.ts, assets.ts
    i18n/                           # routing.ts, request.ts, navigation.ts
```
Rules:
- Pages only import from `@/features/<x>` (the `index.ts` barrel), never deep into components.
- Every internal link uses `Link` from `@/i18n/navigation`, not `next/link`, to keep the correct locale.
- Only add `"use client"` to components that need state (sliders, filters). Keep static sections as Server Components so they stay out of the bundle.
- Heavy data used only for drawing (e.g. the dot string for a world map) should be rendered as SVG on the server, passing only the interactive part down to the client.

## 3. i18n with next-intl
- `routing.ts`:
  ```ts
  defineRouting({ locales: ["vi", "en"], defaultLocale: "vi", localePrefix: "as-needed" })
  ```
  This means `/` is Vietnamese and `/en` is English. Note: `/vi/...` returns 307 to the unprefixed URL.
- `proxy.ts`: `createProxy(routing)`, with matcher `"/((?!api|trpc|_next|_vercel|.*\\..*).*)"`. It must exclude `api` so the webhook is not redirected.
- In layouts and pages, call `setRequestLocale(locale)` to enable static rendering. `generateStaticParams` in the layout returns every locale.
- `request.ts`: in dev, read the JSON with `fs` on every request, because Turbopack sometimes keeps stale JSON and reports MISSING_MESSAGE. In prod, use a static import.
- Structure messages by **page namespace**: `Metadata`, `Common` (nav, shared labels, `productTypes.<slug>`, `materials.<slug>`), `Footer`, `HomePage.<section>`, `<Page>Page.<section>`, `NotFound`. Section keys match section names so they are easy to find.
- CMS content is translated in the CMS (see backend.md §7). UI copy always lives in messages. Never mix the two sources.
- Build the country list on the server with `Intl.DisplayNames` and pass it down to the client, so the server and browser do not translate differently and cause hydration errors.

## 4. Data layer (CMS or mock)
```
data/catalog/
  types.ts         # UI types (Product, SetItem, Dimensions...). Components only know these types
  taxonomy.ts      # category / type / material slugs (translation keys), type → group relations
  index.ts         # pure functions usable on the client (categoryOf, catalogHref...)
  products.mock.ts # mocks with the same Product type
  products.ts      # SERVER-ONLY: getProducts / getProduct / ... chooses CMS or mock
```
Data access function pattern:
```ts
import "server-only";
import { cache } from "react";

export const getProducts = cache(async (locale: string): Promise<Product[]> =>
  cmsEnabled() ? await fetchProducts(locale) : mockProducts);

export const getProduct = cache(async (slug: string, locale: string) =>
  cmsEnabled() ? (await fetchProduct(slug, locale)) ?? undefined : mockProducts.find((p) => p.slug === slug));
```
- React `cache()` deduplicates calls with the same arguments within one render pass, e.g. when `generateMetadata` and the page both call `getProduct`.
- `lib/cms/catalog.ts` maps API types (snake_case, images `{url, thumb, width, height}`) to UI types. It also **filters out unknown slugs** that the frontend has no translation for yet. Lists use the `thumb` image, detail pages use the large image.
- List pages fetch everything once (`cmsGetAll`, `page_size=100`) and filter on the client. This suits a catalog of a few hundred items, because filters respond instantly and the URL still holds the filter state. If the catalog grows to thousands of items, switch to server-side filtering and pagination.

## 5. CMS client, error handling, server-only
Templates: `assets/templates/frontend/src/lib/cms/{client,catalog}.ts`, error page `src/app/[locale]/error.tsx`.
- `CMS_API_URL` has no `NEXT_PUBLIC_` prefix. Leave it empty to use mocks.
- Every fetch:
  ```ts
  next: { tags: ["cms"], revalidate: 3600 }, signal: AbortSignal.timeout(30_000)
  ```
- `cmsGet` returns `null` on 404 (so the page calls `notFound()`), and throws `CmsError(status)` on other errors.
- Put `import "server-only"` at the top of `lib/cms/*.ts` and `data/*/products.ts`, so an accidental import from a client component fails the build immediately.
- **Handling CMS errors:**
  - When the CMS fails, stale-while-revalidate lets Next keep serving the old cached copy; a failed refresh does not overwrite a good cache.
  - If the CMS is down on the first render, `CmsError` bubbles up to `[locale]`'s `error.tsx`. The error page must have the header/footer, a retry button (`reset()`) and a friendly message, without exposing internal URLs.
  - Log errors on the server with `console.error` (collected into the container logs); never show details to visitors.
  - Do not silently "swallow" errors by returning an empty list, because the empty page would then be cached for an hour.
- **Types from OpenAPI:** generate `src/lib/cms/schema.d.ts` from `backend/openapi.yaml` with `openapi-typescript` (pinned version), and add an `npm run cms:types` script. API types in `catalog.ts` come from `components["schemas"][...]`, so TypeScript errors out as soon as the backend changes the API.

## 6. Dynamic pages
```ts
export async function generateStaticParams() {      // prebuilt at build time (default locale)
  return (await getProducts(routing.defaultLocale)).map((p) => ({ category: categoryOf(p.type), slug: p.slug }));
}
export const dynamicParams = true;                   // items published after the build: built on first visit, then cached
```
- Check URL consistency: a correct slug under the wrong group in the URL returns 404.
- Pages whose list is fixed in code (e.g. materials) use `dynamicParams = false`.
- `generateMetadata` reuses the same `resolve()` function as the page (already wrapped in `cache()`).
- If it is a language fallback copy with an untranslated description, add `robots: { index: false }`.

## 7. Images
- `ImagePlaceholder` looks up `config/assets.ts` (the image manifest in `public/Assets`): if the image exists it renders `next/image`, otherwise it shows a striped background with the file name that still needs to be shot. This lets you build the UI before real photos exist. `http(s)` URLs from the CMS pass straight through.
- `next.config.ts`: `images.remotePatterns` is generated from `CMS_API_URL` (`pathname: "/media/**"`). Enable `dangerouslyAllowLocalIP` **only** in dev with the CMS on localhost.
- Always pass `sizes` matching the layout, so the browser does not download images larger than needed.
- Studio product photos on a light background use `object-contain`, so long products are not cropped. Mood photos use `object-cover`.
- Add `priority` to the LCP image (hero); leave other images lazy by default.

## 8. Forms with server actions
Pattern from the BFC Contact form. Run cheap checks first, expensive ones last:
1. Per-IP rate limit (5 times / 10 minutes).
2. Bot traps: a `website` honeypot and submissions that are too fast (< 3 seconds). If caught, pretend it succeeded.
3. Cloudflare Turnstile. Without a site key the widget is hidden and the server skips it in dev.
4. Validate fields with zod, strip control characters.
5. Validate files: extension, size, magic bytes, PDFs with active content.

In addition:
- `useActionState`: errors are returned per field and entered values are kept. On success, replace the form with a confirmation panel.
- The query `?purpose=quote|visit&model=<code>` preselects the purpose and prefills the model code (sanitized values).
- Sending to the CMS: Next calls the CMS write API, HMAC-signed with the same shared secret. The CMS stores the Inquiry in the DB, the file in private storage, then sends an email (fixed recipient; the visitor's email goes only in Reply-To).
- `experimental.serverActions.bodySizeLimit = "11mb"` to accept 10 MB files.

## 9. SEO
- `generateMetadata` for every page; title and description come from messages; `lang` on the `<html>` tag.
- When going to production, add:
  - `alternates.languages` (hreflang vi/en);
  - `app/sitemap.ts` (generated from the catalog), `app/robots.ts`;
  - Open Graph image;
  - JSON-LD `Organization` / `Product`.
- The H1 is the page name. Each section has one h2, even when hidden with `sr-only`.

## 10. Performance
- Static or ISR pages keep TTFB low; the CMS is only called when the cache is stale.
- Server Components by default, client only for interactive parts.
- Fonts via `next/font/google` (Inter, `vietnamese` subset), self-hosted, non-render-blocking.
- Images via `next/image` (WebP/AVIF, correct `sizes`); the CMS already returns WebP renditions.
- Animation:
  - use `IntersectionObserver` or motion's `useScroll`, not `scroll` listeners;
  - count-ups write straight to the DOM via `animate()`, no setState per frame;
  - respect `prefers-reduced-motion`.
- 3D (three.js) is loaded only on pages that need it, via dynamic import.
- **Messages sent to the client:** a `NextIntlClientProvider` without a `messages` prop embeds ALL messages into every page (BFC: HTML of 170 to 210 KB). As the site grows, pass only the namespaces client components need (`messages={pick(messages, ["Common", ...])}`), or move the component to the server.
- Security headers in `next.config.ts`: `nosniff`, `X-Frame-Options SAMEORIGIN`, `Referrer-Policy`, `Permissions-Policy`.
